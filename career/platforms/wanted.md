# 원티드 접근·관리

## 목적과 표현

웹·모바일 개발 직무의 공고 탐색과 직접 지원을 주요 용도로 사용한다. 면접 제안용 프로필도 함께 관리한다. [원티드 면접 제안 안내](https://www.wanted.co.kr/matchup/intro)는 이력서를 바탕으로 채용 담당자가 면접을 제안하는 기능을 설명한다.

소개와 대표 성과는 React·TypeScript·React Native 경험을 우선 배치한다. 지원 직무에 따라 프론트엔드 개선, 모바일 연동, 제품 개발 사례의 순서를 조정한다. AI 도구 활용은 직접 책임진 설계·검토·검증 과정과 함께 표현한다.

## 접근

- 시작점: [원티드](https://www.wanted.co.kr/).
- Ego Lite의 로그인된 본인 계정에서 이력서·프로필 관리 화면을 찾는다.
- 이력서 편집, 파일 첨부, 면접 제안 설정, 지원 현황의 실제 메뉴·입력 제한을 첫 작업에서 확인한다.
- 이력서가 여러 개라면 선택된 기본 이력서와 공고에 제출되는 자료를 구분한다. 기존 이력서는 승인 없이 삭제하지 않는다.

## 사이트 URL·로그인 방식

| 용도 | URL·진입 경로 |
|---|---|
| 공식 사이트·채용 탐색 | [www.wanted.co.kr](https://www.wanted.co.kr/) |
| 로그인 진입 | 공식 사이트의 로그인 버튼 → Wanted OneID |
| 인증 서비스 | `https://id.wanted.co.kr/` 도메인의 로그인 화면 |
| 면접 제안 안내 | [면접 제안](https://www.wanted.co.kr/matchup/intro) |
| 도움말 | [원티드 고객센터](https://help.wanted.co.kr/) |
| 이력서 목록 | [이력서 관리](https://www.wanted.co.kr/cv/list) |
| 지원 현황 | [지원 현황](https://www.wanted.co.kr/status/applications/applied) |
| 지원·면접 제안 | [제안 목록](https://www.wanted.co.kr/status/proposal?kind=OFFER) |
| MY 원티드 | [본인 프로필](https://social.wanted.co.kr/my/profile) |

- 기본 방식: 기존 Ego Lite 세션을 재사용한다. 세션이 없으면 공식 사이트의 로그인 버튼에서 Wanted OneID로 이동해 **Google 계정으로 계속하기**를 선택한다.
- [공식 OneID 로그인 화면의 검색 결과](https://id.wanted.co.kr/login?before_url=https%3A%2F%2Fwww.wanted.co.kr%2Fcompany%2F5f5dd0f1cd094877e4780eb84f2d7d116d41b74c&client_id=AhWBZolyUalsuJpHVRDrE4Px&service=wanted)에서 **카카오·Apple·Google 계정, 이메일로 계속하기**를 확인했다. 이 링크는 방식 확인용 출처이며 운영 진입점은 원티드 홈의 로그인 버튼이다.
- OneID URL의 `client_id`, `service`, `before_url` 같은 서비스·복귀 정보는 사이트가 생성한 값을 사용한다. 다른 서비스의 인증 링크를 복사하거나 매개변수를 임의로 조립하지 않는다.
- 기존 가입 방식으로 로그인한다. 이메일 방식의 후속 비밀번호·인증 단계는 실제 화면에서 확인하며, 신규 가입으로 기존 이력서를 대체하지 않는다.
- 로그인 후 본인 이력서와 지원 현황이 연결돼 있는지 확인한다. 소셜 인증·추가 인증은 사용자에게 넘긴다.
- 사용자 계정의 실제 로그인 수단: **Google 계정**. 2026-10-01 사용자 직접 확인. 같은 날 Ego Lite의 원티드 홈에서 로그인된 세션과 이력서·지원 현황 링크를 확인했다. 계정 화면은 알림 권한 팝업으로 확인이 중단됐으며 Google 인증 절차 자체는 직접 검증하지 않았다.
- 확인일: 2026-10-01. 공개 웹 직접 조회는 제한됐고 Ego Lite에서는 알림 권한 팝업으로 화면 확인이 중단됐다. 로그인 방식은 공식 OneID 검색 결과 기준이다.

## 반영·검증 절차

1. 현재 이력서와 선택·제출 상태를 확인한 뒤 최신 자료와 차이를 정리한다.
2. 현재 필드에 맞게 문안을 작성한다. PDF 업로드가 편집 필드를 자동으로 갱신한다고 가정하지 않는다.
3. 저장 후 새로고침과 미리보기로 확인한다. 자동 저장 방식이라면 저장 상태 표시와 다시 열었을 때의 내용을 확인한다.
4. 긴 경력·프로젝트 문안과 링크, 첨부 PDF를 확인한다. 실제 화면을 읽어 가독성을 점검한다.
5. 제출 전에 해당 공고에 선택된 이력서·파일이 승인된 버전인지 확인한다.

## 공고·지원 관리

필수 기술·담당 업무·경력 요건을 현재 경험과 대조한다. 프론트엔드와 모바일 포지션은 서로 다른 대표 사례를 먼저 제시할 수 있다. 지원 버튼을 누르기 전 회사·포지션·자료·추가 질문을 확인하고, 승인된 지원만 제출한다. 접수 완료와 지원 현황을 확인해 기록한다.
