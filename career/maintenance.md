# 정기 이력 관리

작성일: 2026-10-01. 매주 토요일 활동을 수집하고 매월 초 사용자와 사실·공개 범위를 검토한 뒤, 확정된 변경분만 포트폴리오·이력서·구인 사이트에 반영한다. 최초 전체 정비 이후에는 새 활동과 정정 사항을 중심으로 관리한다.

이 문서는 운영 절차와 빈 기록 양식이다. 예약 작업을 생성하거나 실행 권한을 확대하지 않는다. 실제 반영 전 대상 채널·문안·파일·공개 범위를 사용자와 확인하고, 이미 승인된 동일 작업의 범위는 유지한다. 구인 사이트별 저장·업로드·게시, 지원·메시지·공개 설정은 [플랫폼 운영 기준](platforms/README.md)의 승인 범위를 따른다.

## 기준 문서와 기록 위치

- [경력 자료 안내](README.md): 근거 수집, 개인 담당 범위 확인, 공개 자료 분리.
- [경력·학력·자격증 기준](facts/README.md): 사용자 확인·정정의 우선순위, 고정 사실과 파생 정보, 변경 이력.
- [젠테라 경력 기준](facts/xenterra.md): 확인된 담당 범위와 확대하지 않을 표현.
- [이력서 검토 기록](channels/resume/review-notes.md): 사실 검증·기밀 보호의 기존 검토 근거. 로컬 전용·Git 추적 제외이며 공개 문안에 원문을 복사하지 않는다.
- [이력서 문안](channels/resume/README.md), [LinkedIn 문안](channels/linkedin/README.md), [GitHub 문안](channels/github/README.md): 채널별 작성 기준.
- [최신 이력서 관리](releases/resume/README.md), [최신 원고](releases/resume/latest/resume.md): 검토 후 제출본 갱신 기준.

회사의 코드·내부 문서·운영 데이터 등 증빙은 기존 `career/evidence/`의 비공개·Git 제외 정책을 따른다. 원자료의 원문과 출처를 보존하고 검토한 공개 문안만 분리한다. 주간 활동·월간 결정·채널 반영 기록은 기존 Git 제외 경로인 `output/job-search/` 아래에서 관리한다. 예: `weekly/YYYY-MM-DD.md`, `monthly/YYYY-MM.md`, `channel-updates.md`. 이 문서에는 실제 계정·지원 내역·회사 증빙을 채우지 않는다.

## 매주 토요일: 활동 수집

지난 수집 이후의 변경과 이전 미확인 사항의 새 근거를 모은다. 활동별 식별값을 붙여 같은 작업을 다음 주에 중복 성과로 세지 않는다. 수집 단계에서는 외부 프로필을 갱신하지 않는다.

아래 양식을 활동별로 복사한다. 사실·사용자 진술·추정·미확인을 구분하고, 근거에는 무엇을 확인했는지와 확인하지 못한 범위를 함께 적는다.

| 필드 | 기록할 내용 |
|---|---|

| 기간 | 실제 작업 시작·종료 또는 진행 기간. 모르면 미확인 |

| 직접 담당한 일 | 구현·설계·검토·통합·검증 등 본인 수행 범위와 팀·AI 도구의 작업 구분 |

커밋 수·작성자·AI 세션 수는 개인 기여율이나 성과 수치가 아니다. 측정하지 않은 개선율·사용자 수·매출·성공률과 과장된 단독 개발·전체 소유 주장은 금지한다. 수치가 없어도 근거로 확인된 문제·작업·변경 결과는 기록할 수 있다.

## 매월 초: 사용자와 공동 검토

직전 검토 이후 수집된 활동과 이월 질문을 검토한다. 월초의 구체적인 날짜·시각은 사용자와 조율하며 이 문서만으로 자동 실행하지 않는다.

- [ ] 프로젝트의 개인·회사·외주 구분과 본인 역할, 재직·수행 기간을 확인했다.
- [ ] 근거가 증명하는 구현 범위와 사용자 진술, 추정·미확인을 구분했다. 팀 전체 작업을 개인 성과로 옮기지 않았다.
- [ ] 진행·완료·병합·배포·실제 사용을 구분했다. 결과 수치의 측정 조건과 출처를 확인했다.
- [ ] 비공개 회사 정보·개인정보·고객사·내부 경로·구현 세부의 공개 가능 여부를 확인했다. 미확인 내용은 비공개 기록에 보류했다.
- [ ] 기존 기준과 새 근거의 차이를 대조하고 사용자 정정·변경 사유를 기록했다. 오래된 문안으로 확정 사실을 덮어쓰지 않았다.
- [ ] 대표 성과로 추가·수정할 항목, 보류·제외할 항목, 변경이 없는 항목을 골랐다. 모든 활동을 이력서에 나열하지 않았다.
- [ ] 채널별 표현·분량·대상 직무를 정하고, 사실·기간·담당 범위가 서로 일치하는지 확인했다.
- [ ] 실제 반영할 채널·문안·파일·공개 범위를 사용자와 확인했다. 외부 반영 권한과 미확인 질문을 남겼다.

## 확정된 변경분 반영 순서

1. **기준 사실 문서:** 해당 회사·학력·자격증·활동의 기준 문서에 새 확인과 변경 이력을 먼저 기록한다. 개인·외주 프로젝트도 공개 문안을 사실 원본으로 삼지 않고 확인된 사실·근거를 기준 기록으로 남긴다. 내부 근거의 상세 내용은 비공개 기록에 보존한다.
2. **채널별 문안:** 확인된 변경만 이력서·포트폴리오·플랫폼 문안에 반영한다. 지원 직무에 따라 순서·분량을 달리해도 사실·기간·개인 담당 범위를 확대하지 않는다. 웹 표시 데이터는 채널의 표현이며 사실 기준을 대체하지 않는다.
3. **제출본:** 검토한 원고로 `career/releases/resume/latest/`의 원고·PDF를 갱신하고, 웹 제공 PDF를 같은 최신 파일과 대조한다. PDF는 실제 페이지를 확인한다. 이전 이력서 파일을 삭제한 기존 정책을 바꾸거나 새 보관본을 자동으로 만들지 않는다.
4. **채널 반영:** 사용자와 확인한 범위에서 변경된 채널만 갱신한다. 변경 없는 채널은 수정 없이 기준 버전과 일치 여부만 확인한다. PDF 교체와 플랫폼 편집 필드 갱신은 각각 확인하고, 진행 중인 다른 스레드의 파일·작업은 덮어쓰지 않는다.
5. **결과 검증:** 아래 기록에 저장·화면·게시 확인과 남은 작업을 남긴다. 필요한 확인이 실패하거나 권한·인증이 없으면 해당 채널을 완료로 표시하지 않는다.

매월 전체 이력을 다시 작성하지 않는다. 전체 점검은 최초 정비, 재직·담당 범위 정정, 제출 형식 변경이나 채널 간 불일치가 확인됐을 때 해당 범위에서 수행한다.

## 반영·저장·게시 검증

- 포트폴리오: 로컬 문안·PDF 확인과 운영 게시 확인을 나눈다. 배포한 경우에만 실제 운영 URL의 표시 내용·링크·다운로드 파일을 확인한다.
- 이력서: 최신 원고와 PDF의 내용·페이지, 웹 다운로드 PDF의 일치 여부를 확인한다. 파일의 SHA-256은 동일 파일을 식별하는 값이며 내용의 사실 검증을 대신하지 않는다.
- 구인 사이트: 플랫폼 운영 기준에 따라 저장 후 새로고침·다시 열기·미리보기로 내용 유지와 잘림, 날짜·링크·첨부 파일을 확인한다. 가능한 경우 첨부 PDF를 내려받아 해시를 비교하고, 불가능하면 파일명 확인 등 실제 확인 수준을 기록한다.
- 공개·게시: 로그인된 편집 화면의 저장 확인과 외부 공개 화면 확인을 나눈다. 비공개 프로필·지원용 첨부는 의도한 노출 범위를 기록하며 공개 설정을 임의 변경하지 않는다.
